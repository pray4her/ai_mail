
项目：企业级 AI 邮件自动回复系统

项目架构：通过 IMAP 拉取邮件 -> 知识库检索（Hybrid Search / RAG）
-> 生成可直接发送给用户的 AI 自动回复邮件。


系统已完成
1. 完成上述功能模块，实现从邮件服务器 -> 知识库检索（已解析文档向量化搜索和关键词检索）-> 提示词组装 -> AI 模型生成待回复邮件 -> 邮件草稿生成
2. 系统初期采用mysql数据库存向量、同时使用全文检索索引来检索关键词，目前已经全面迁移到ES，但保留已完成测试的实现
3. 系统完成多种AI大模型的使用测试，包括oll本地部署Qwen2.5
4. 系统完成配套前端界面，同时前端提供动态配置界面、后端同样实现动态配置类ConfigService（从config.json读取配置）
5. 系统预留了扩展接口（包括邮件入库、邮件服务器imap推送、邮件操作如移动、复制等），方便后续添加新的功能模块，同时在TODO中标注未启用模块和待优化功能
6. 系统的主要功能由定时任务（Schedule）执行，包括定时解析知识库文档、定时自动回复邮件（后续可该改变定时任务时间），默认定时解析文档间隔15分钟，邮件获取为动态执行时间


系统新需求

1.  可以对某段时间的邮件进行历史入库和上下文解析
2.  系统启动时新用户不进行邮件回复（已修改、未测试），只进行历史邮件入库

系统优化

1. 知识库检索目前采用ES，并且分片算法采用贪心，后期确实可以迁移到索引机制，来实现更精确的知识库片段匹配
2. 在上述的上下文管理中，我们可以引入threadId来做会话管理，将相同会话的邮件归类为一个会话，从而实现更精确的上下文匹配
3. promptBuilder生成提示词优化，加入role、优先级、上下文（可选）
4. 对数据一致性做一个状态表管理，或使用消息队列
5. 系统目前使用Tika解析文档，可以使用OCR接口进行文档解析，同时可以根据知识库文档类型进行不同的解析设置。
6. 目前采用定时轮询邮件服务器是否有新邮件，可以考虑imap的推送机制
7. 调用阿里向量化接口可以使用batch批量请求
8. 去除文档解析的定时任务，在文档上传时直接调用解析(已完成、已测试)
9. 系统目前运行方式采用虚拟机cmd+jar运行，后续可以考虑使用docker进行容器化部署

系统注意事项

1.  系统使用的es有ik分词插件，如果迁移es需安装，并修改yml配置中的https密码和证书文件
2.  系统使用java 17 + mysql 8.3 + elasticsearch-8.10.0 + minio
3.  MySQL 表结构以 Flyway 迁移为准，迁移文件位于 `src/main/resources/db/migration`；旧的 `mail.sql`、`schema.sql` 和 `db_upgrade_history_sync.sql` 仅作为历史参考
4.  数据库默认用户 root 密码123456，在yml文件中配置
5.  minio默认用户  minioadmin 密码  minioadmin，桶名称为uploads
6.  系统目前默认上传文件大小上限为20M，请求体上限为25M （在yml中设置）（内网环境）
